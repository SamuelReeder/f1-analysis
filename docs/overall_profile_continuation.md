# Recovery of the interrupted complete-design profile

This is an execution-recovery definition for the
[preserved interruption](../outputs/championship/development/overall-complete-design-profile-v1-interruption/interruption.json),
not a new statistical experiment or a change to the model. Implementation and a
frozen continuation registration are required before it can run. The
[planner](../analysis/overall_profile_continuation.py) and
[execution controller](../analysis/overall_profile_continuation_run.py) are now
prepared; their [focused software checks pass](../outputs/championship/development/overall-profile-continuation-checks-v1/verification.json).
The [saved-archive audit](../outputs/championship/development/overall-interrupted-profile-diagnostics-v1/audit.json)
has also completed with every recorded coordinate and driver-contrast report
reproduced exactly. The original failed attempts remain failed. A frozen
execution registration and service launch are still required.
The original
profile remains immutable and incomplete; its history must never be rewritten
to look uninterrupted.

## Eligibility before execution

Require the explicit interrupted-run metadata review to pass and require exact
reproduction of every available saved coordinate and driver-contrast report.
Bind the committed reviews, their source identities, original interruption
observation, registration, model/data fingerprints, complete output inventory and
all original archive fingerprints. A reproduced failed report remains failed.
Recorded divergence counts are inputs to report reproduction because the original
sampler extras were not archived; do not describe those counts as independently
verified.

Require an authoritative new inspection of the original service and execution
environment. A live process cannot be replaced because a status file is absent.
Require the saved receipt to remain interrupted, with no terminal fit decision.
Each preceding attempt must have its complete matching record and verified
archive, and must have failed its original convergence gate. An earlier success,
an exhausted failure ladder, a changed input, an unexplained extra attempt or an
unaccounted partial file makes this continuation ineligible.

The last sampling-start event must name exactly the next registered attempt and
its original settings. No completed report or draw archive may exist for that
unfinished attempt. The recorded interrupted event is real-network attempt **3**,
with seed **2**, as preserved in the interruption record and original log. Its
sampler state was not checkpointed. Recovery therefore restarts that attempt
from its registered seed; it cannot resume partway through warmup or sampling.

## Unchanged numerical work

Regenerate the original case with its original generating seed and require exact
agreement with every preflight observation, parameter, truth and control-map
fingerprint. Use the original complete-profile sampling function, bounded
diagnostic checker, current-driver contrast function, coordinate map and complete
retained-site inventory. Bind their existing source hashes and runtime settings.
Do not substitute the prepared batching implementation or any new model code.

Retain the original completed attempts as historical records with their original
durations and diagnostics. Do not resample or re-time them. Restart only the
unfinished registered attempt. If that attempt misses the original gate, run
only the remaining step in the same fixed retry ladder with its original seed
and settings. A success ends the ladder; an exhausted ladder remains failed.
An exception or resource failure is recorded and stops this execution. There is
no automatic restart following another interruption.

Use a new immutable continuation output and cache directory. Never overwrite the
original receipt, attempts, logs, draws or partial progress. Existing failed draw
archives may be referenced or linked by their verified identities; no writer may
modify those files. New attempts use distinct previously absent filenames.
Record the continuation implementation and registration separately from the
unchanged scientific specification. Preserve both provenance chains.

## Resources, evidence and stopping

The user-requested shared CPU cap remains **400%**, with weight **10**, nice **19**
and a maximum aggregate fit budget of **13G**, as specified in the
[current resource policy](overall_model_plan.md). Verify service membership and
actual limits before sampling. No other fit or heavy check may overlap the
continuation. The original registration's earlier CPU cap remains historical;
never restore it silently to satisfy an old launcher check.

Run software checks before freezing and committing the continuation registration.
The registration must bind the exact implementation, tests, definition,
prerequisite evidence and unchanged original scientific settings. Check source
and data identities before and after every actual sampling attempt. Retain every
new diagnostic report and complete draw set, including failures, and record
external exit/resource evidence even when the worker cannot write its own result.

Keep execution segments distinct. Original saved-attempt durations are not the
cost of copying or verifying them, and continuation runtime is not the original
whole-run wall time. The original interrupted peak and duration remain unknown.
The continuation's measured memory and elapsed time describe its own process.
Keep the original mid-run CPU reduction and unknown restart cause visible.

Any combined computational-profile report must reference the original completed
cases and the separately recorded continuation result. Missing or failed cases
remain required failures. Such a report must not fabricate an original summary,
child exit code or uninterrupted success. A complete computational profile would
still precede full recovery, simulation-based calibration, functional precision,
predictive validation and production acceptance. No continuation result can
advance the public ranking pointer or authorize deployment by itself.
