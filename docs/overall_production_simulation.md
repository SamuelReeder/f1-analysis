# Registered candidate simulation and export

The production controller connects a registered joint posterior to the common
calendar, paired explanations, bounded summary, grouped diagnostic moments and
portable export components. It is an execution stage of the canonical Overall
pipeline. Its artifacts remain unpublished candidate evidence. It never supplies
scientific acceptance or advances a dashboard pointer.

The mathematical implementation is the existing paired simulation and summary.
The original research implementations and historical results remain unchanged.
Their runtime copies live under `f1rank/overall/` and import no research modules.
Source identities record the new locations. The controller binds all Python
sources in the production package, the shared contract and its scientific
definitions; an added, removed or changed runtime source invalidates execution.

## Required inputs

Commit the simulation protocol before execution. It records the complete source
inventory and runtime identity, fit receipt and posterior hashes, training arrays
and catalog, grouped draw shape, fixed seed and block schedule, replicate count,
qualifying format, full reference artifact and race-control assumptions. It also
binds the fit registration's path and bytes, the fit's synthetic or real-data
role, names for every entrant, and the scenario label used in export components.

The fit registration must select the explicit production inference implementation
and bind the fit's current source identity. Its study, purpose, settings, seeds
and entire completed retry sequence must agree with the receipt. Synthetic
registrations cannot be relabeled as real-data acceptance fits. Real-data
registration and scoring still require the complete scientific protocols in the
[candidate contract](overall_candidate.md). This controller verifies execution
identities; it does not certify that the scientific work has been completed.

The fixed reference scenario uses the existing complete calendar/context mapping
and equal event weights. Missing circuits, mismatched field entries, future
reference events or absent race-control assumptions are rejected. Unresolved
reference assumptions remain in the result. Reading that artifact does not
establish its historical availability or calibration.

## Execution and reads

Each output directory is immutable. The controller visits every chain, posterior
draw and registered replicate block, with the existing fixed random-stream
addressing and common randomness for explanations. Every saved posterior member
is validated, including unused arrays; selected fields are read through bounded
temporary memory maps. Source, receipt and archive checks remain active through
the consumer's successful exit. Every completed fit attempt's sampler extras
must still match the fitting receipt.

Only a complete simulation writes a summary and grouped moments. The receipt
records the visited block inventory, complete input identities and output hashes.
Exceptions preserve the running progress and final failure record. There is no
automatic retry, adaptation of precision settings or partial-result cache.

The fixed conditional precision criteria determine whether `components.json`
can be written. Failure preserves the diagnostic summary without export
components. Successful components retain paired differences and explanation
uncertainty directly; marginal intervals are never subtracted. They retain
`scientific_evidence_verified: false` and `publication_allowed: false`, and have
no public status or schema. They cannot be read as an accepted dashboard result.

The candidate reader rechecks the committed protocol, sources, reference,
registered fit, posterior identity, complete schedule, summary and moments. If
components exist, it reconstructs them from the checked summary and requires an
exact match. Missing, stale, incomplete or mixed artifacts fail. This supplies a
checked execution artifact for the later acceptance controller, not that
controller's decision.

## Verification and remaining requirements

Verify migrated arithmetic against the existing implementation; complete paired
outputs and source identities; registered synthetic/real role separation; fixed
retry correspondence; bounded archive loading; complete block coverage;
preservation of failed precision; export identity; and mutation rejection.
Use invented cache-format fixtures for software checks. Their diagnostic success
fields are test doubles and never scientific evidence about a driver.

The failed full-network inference remains failed. Complete scientific protocols,
recovery and calibration, functional MCMC and near-tie precision, independent
predictions, reference assumptions, full workload resources, authenticated
acceptance, canonical dashboard publication and refresh/rollout remain required
by the [full plan](overall_model_plan.md). No new fit or scientific run is
authorized by this execution definition.
